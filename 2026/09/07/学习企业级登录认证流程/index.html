企业级登录认证鉴权完整流程解析（Spring Cloud Gateway + Sa-Token + Redis）

一、架构总览

项目采用 Spring Cloud Gateway + Sa-Token + Redis 的微服务统一鉴权方案，认证逻辑拆分为三个模块协作：

模块 职责
xiaohashu-gateway（8000，WebFlux） 统一入口：路由转发、Sa-Token 登录/权限校验、Token→userId 解析透传
xiaohashu-auth（8080，Servlet） 登录/注册/登出/改密/发验证码，调用 StpUtil.login() 颁发 Token
xiaohashu-user 用户、角色、权限数据；注册时分配角色；启动时把角色权限同步到 Redis
xiaoha-spring-boot-starter-biz-context 公共组件：请求头 userId → ThreadLocal，Feign 调用透传

核心设计思想：Token 会话集中存储在 Redis（非 JWT 无状态方案），auth 服务颁发、gateway 校验、两端共享 Redis；下游服务不接触 Token，只接收网关注入的 userId 请求头。

Redis Key 设计：

Key Value 写入时机
role:permissions:{roleKey} ["app:note:publish",...] 权限标识 JSON 服务启动预热
user:roles:{userId} ["common_user",...] 角色标识 JSON 用户注册时
Authorization:login:token:{token} userId（Sa-Token 自动维护） 登录成功时

注意：Sa-Token 的 token→loginId 存储 Key 前缀规则是 {token-name}:login:token:，因配置了 token-name: Authorization，所以前缀正好是 Authorization:login:token:，网关常量与此对应。

四、Token 生成与存储机制

依赖整合（Maven 关键依赖）：

  • auth（Servlet 环境）：sa-token-spring-boot3-starter + sa-token-redis-jackson
  • gateway（WebFlux 环境）：sa-token-reactor-spring-boot3-starter + sa-token-redis-jackson

sa-token-redis-jackson 让 Sa-Token 的会话默认存储从内存切换到 Redis，auth 写入、gateway 读取，两端共享同一个 Redis 实例，这是微服务下会话共享的关键。

会话策略配置（auth 与 gateway 的 application.yml 完全一致，保证 Token 规则统一）：

StpUtil.login(userId) 执行后，Sa-Token 自动完成：

  1. 生成 128 位随机 Token 字符串；
  2. 写入 Redis：Authorization:login:token:{token} → userId，TTL 30 天；
  3. 后续每次请求自动续期（Sa-Token 默认活性续期机制）。

前端拿到 Token 后，后续所有请求在 Header 携带：Authorization: Bearer {token}。

七、会话管理策略

策略 实现
会话存储 Redis 集中存储，支持多服务共享、水平扩展；区别于 JWT，服务端可主动失效（踢人/登出）
Token 有效期 30 天，Redis TTL 自动过期；Sa-Token 默认访问续期
多端登录 is-concurrent: true + is-share: true，同账号多端共用一个 Token
登出 StpUtil.logout(userId) 删除 Redis Token 记录，后续请求立即失效
验证码会话 Redis Key 3 分钟过期 + hasKey 判断防重复发送
权限缓存 角色权限预热到 Redis，push.permission.flag 分布式锁 1 天，每日自动重同步
上下文生命周期 请求级 ThreadLocal，Filter 的 finally 中清理；TTL 保证异步线程可用

九、完整时序总结

一次完整登录访问的时序如下：

  1. 发验证码：POST /auth/verification/code/send（网关白名单）→ 生成 6 位码存 Redis（3 分钟）→ 线程池异步调用阿里云短信下发；
  2. 登录：POST /auth/login（白名单）→ 校验 Redis 验证码或 BCrypt 密码比对 → Feign 调 user 服务注册/查询用户（注册时分配默认角色并写 user:roles:{userId}）→ StpUtil.login(userId) 写 Redis 会话 → 返回 Token 给前端；
  3. 携带 Token 访问业务接口：Header 携带 Authorization: Bearer {token} → 网关 SaReactorFilter.checkLogin() 查 Redis 校验登录态 → 需要权限时回调 StpInterfaceImpl 从 Redis 读取角色权限（user:roles + role:permissions）→ AddUserId2HeaderFilter 用 Token 查 Redis 得到 userId 并注入请求头；
  4. 下游服务处理：服务 HeaderUserId2ContextFilter 将请求头中的 userId 存入 TTL ThreadLocal → 业务代码通过 LoginUserContextHolder.getUserId() 取用 → Feign 跨服务调用时 FeignRequestInterceptor 自动透传 userId 请求头；
  5. 异常与登出：未登录或权限不足由网关全局异常处理器统一返回 HTTP 401 与标准错误体；登出调用 StpUtil.logout(userId) 删除 Redis 会话，Token 立即失效。

方案要点回顾：

  • 网关统一鉴权，业务服务保持纯净，不引入安全框架；
  • 会话基于 Redis 集中存储，相比 JWT 支持服务端主动失效，auth 与 gateway 共享 Redis 完成会话共享；
  • 角色权限数据预热 + 用户角色注册时写入，网关鉴权全程只查 Redis，不打数据库；
  • userId 通过”请求头 + ThreadLocal + Feign 拦截器”在网关与微服务、微服务与微服务之间透传，形成完整身份链路。
