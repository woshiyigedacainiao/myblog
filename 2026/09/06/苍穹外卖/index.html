公共字段自动填充功能技术文档

1. 整体架构概述

公共字段自动填充功能是一个基于AOP（面向切面编程）的解决方案，用于在数据库操作时自动填充如创建时间、更新时间、创建人、更新人等公共字段。该功能通过自定义注解、切面编程和反射机制实现，避免在每个实体类的CRUD操作中重复编写相同的字段赋值代码。

2. 核心组件分析

2.1 自定义注解 - AutoFile

2.2 操作类型枚举 - OperationType

2.3 常量类 - AutoFillConstant

2.4 上下文工具类 - BaseContext

2.5 切面类 - AutoFileAspect

3. 实际应用示例

3.2 实体类要求

4. 核心流程解析

4.1 自动填充流程图

4.2 详细步骤说明

  1. AOP切入
    • 定义切入点表达式，匹配所有在com.sky.mapper包下且标注了@AutoFile注解的方法
    • 使用@Before前置通知，在目标方法执行前进行拦截
  2. 获取操作类型
    • 通过反射获取方法上的@AutoFile注解
    • 获取注解中的OperationType值（INSERT或UPDATE）
  3. 获取实体对象
    • 从JoinPoint中获取方法参数
    • 取第一个参数作为需要填充的实体对象
  4. 获取填充数据
    • 从BaseContext中获取当前登录员工ID
    • 获取当前系统时间作为时间戳
  5. 反射设置字段值
    • 根据操作类型确定需要填充哪些字段
    • 使用反射机制调用实体类的setter方法
    • 设置对应字段的值

5. 关键特性

5.1 操作类型区分

  • INSERT操作：填充创建时间、更新时间、创建人、更新人四个字段
  • UPDATE操作：仅填充更新时间、更新人两个字段

5.2 反射机制

  • 通过反射动态调用实体类的setter方法
  • 不依赖具体的实体类类型，具有良好的通用性

5.3 线程安全

  • 使用ThreadLocal存储当前用户ID，确保线程安全
  • 每个线程都有独立的用户上下文

6. 使用约束

6.1 实体类要求

  1. 必须包含标准的setter方法（遵循JavaBean规范）
  2. 公共字段必须包括：
    • createTime: LocalDateTime类型
    • updateTime: LocalDateTime类型
    • createUser: Long类型
    • updateUser: Long类型

6.2 Mapper层要求

  1. 需要在需要自动填充的方法上添加@AutoFile注解
  2. 注解参数必须指定操作类型（INSERT或UPDATE）

7. 异常处理

7.1 异常类型

  • NoSuchMethodException: 实体类缺少对应的setter方法
  • IllegalAccessException: setter方法不可访问
  • InvocationTargetException: setter方法执行异常

7.2 异常处理策略

  • 捕获所有反射相关异常
  • 记录详细错误日志
  • 不中断主要业务流程

8. 优势分析

8.1 代码复用性

  • 避免在每个实体类的CRUD操作中重复编写字段填充代码
  • 一处定义，多处使用

8.2 维护性

  • 当需要修改公共字段规则时，只需修改切面类
  • 不需要修改业务代码

8.3 一致性

  • 确保所有实体类的公共字段填充逻辑一致
  • 防止人为疏忽导致字段未填充

9. 注意事项

  1. 性能影响：由于使用了反射机制，会有一定的性能开销
  2. 调试复杂度：AOP可能增加调试的复杂度
  3. 实体类规范：要求实体类必须遵循JavaBean规范
  4. 线程安全：确保BaseContext的正确使用，避免跨线程数据污染

10. 扩展建议

  1. 支持更多字段类型：可以扩展支持更多类型的公共字段
  2. 条件填充：可以根据某些条件决定是否进行填充
  3. 批量操作支持：扩展对批量操作的支持
  4. 缓存优化：对反射获取的方法进行缓存，提高性能

文件上传功能基于阿里云OSS（Object Storage Service）实现，主要用于存储系统中的图片资源，如菜品图片、分类图标等。该功能采用前后端分离架构，后端提供文件上传接口，前端调用接口完成文件上传。

3.2 详细步骤说明

  1. 前端发起上传请求

    • 前端发送POST请求到 /admin/common/upload
    • 请求内容为multipart/form-data格式的文件数据
  2. Controller接收处理
    • 接收MultipartFile类型的文件参数
    • 提取原始文件名
    • 生成唯一的UUID作为新文件名，避免文件名冲突
    • 转换文件为字节数组
  3. 调用OSS工具类
    • 通过依赖注入获取AliOssUtil实例
    • 调用upload方法上传文件
    • 传入文件字节数组和生成的新文件名
  4. OSS上传处理
    • 使用阿里云OSS SDK创建客户端
    • 设置上传参数和元数据
    • 执行上传操作
    • 返回文件访问URL
  5. 结果返回
    • 成功：返回Result.success(filePath)，包含文件访问路径
    • 失败：返回Result.error()，包含错误信息

  • 前端：获取微信登录凭证(code)
  • 后端：处理微信登录请求并返回JWT令牌

3. Cron表达式详解

Cron表达式由6或7个字段组成，格式如下：

常用符号含义：

  • : 匹配任意值
  • /: 步长，如0/5表示从0开始，每隔5个单位
  • ,: 列表，如1,3表示1和3
  • : 范围，如1-3表示1到3
  • ?: 不指定值，用于日和星期字段

系统中使用的表达式示例：

  • "0/5 * * * * ?": 每5秒执行一次
  • "0 */1 * * * ?": 每分钟执行一次
  • "0 0 1 * * ?": 每天凌晨1点执行一次

4. @Scheduled注解

主要属性

  • cron: 使用Cron表达式定义执行时间
  • fixedRate: 固定频率执行（毫秒）
  • fixedDelay: 固定延迟执行（毫秒）
  • initialDelay: 首次执行前的延迟时间

6. 最佳实践

1. 任务分离

将不同类型的任务放在不同的方法中，便于管理和维护。

2. 异常处理

定时任务应考虑异常情况，避免因单次执行失败影响后续执行。

3. 日志记录

使用日志记录任务执行情况，便于调试和监控。

4. 性能考虑

  • 对于大数据量的操作，考虑分批处理
  • 合理设置执行频率，避免过于频繁地占用系统资源
  • 在高并发场景下，考虑加锁防止重复执行

7. 注意事项

1. 并发执行

默认情况下，定时任务是串行执行的，如果一个任务执行时间长，会影响其他任务的执行时机。

2. 时间格式

确保服务器时间准确，特别是跨时区部署时。

3. 任务幂等性

设计任务时要考虑幂等性，即使多次执行也不会产生副作用。
