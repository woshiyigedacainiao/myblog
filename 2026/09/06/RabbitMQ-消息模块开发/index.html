一、死信队列（DLX）实现延迟消息

1.1 什么是死信队列

死信队列（Dead Letter Exchange，DLX）是一种消息机制：当消息在队列中满足以下条件时，会被自动转发到另一个交换机（死信交换机）：

  • 消息过期（TTL 超时）
  • 消息被拒绝（basicNack / basicReject，且 requeue=false）
  • 队列达到最大长度

1.4 ⚠️ 踩坑：注解方式无法配置死信

用 @RabbitListener 的 @QueueBinding 注解可以自动创建交换机和队列，但无法设置 x-dead-letter-exchange 等参数。需要死信功能的队列，必须在配置类中手动声明为 @Bean。

2.2 解决原则

发送的内容 接收时怎么处理
String（如 orderNo） new String(message.getBody()) 直接拿
对象（如 OrderDto） JSONUtil.toBean(...) 反序列化
基本类型（如 Long） 同样 new String(message.getBody()) 再转换

记住：发什么类型，收什么类型，必须一一对应。

2.3 设计建议

延迟消息只发必要的最小信息。30分钟后超时取消只需要 orderNo，不需要整个 OrderDto：

  • 减少消息体积
  • 避免数据过期不一致
  • 用 orderNo 去数据库查最新数据即可

四、幂等性检查的位置

4.1 踩坑：幂等检查放在扣库存之后

后果：重复用户的库存被白白扣掉，而且抛异常后消息重新入队，又扣一次。

4.2 正确顺序

原则：越靠前的检查，越能避免无效操作。幂等检查只需要一次 Redis 查询，成本极低，应该放在最前面。

十、代码规范小记

规范 说明
Redis key 统一放常量类 RedisKeyConstant.ORDERED_KEY，不要硬编码字符串
工具方法封装成 Helper 如 RedisStockHelper，复用且语义清晰
变量命名要准确 deliveryTag 不要写成 consumerTag
未使用的 import 及时清理 保持代码整洁
