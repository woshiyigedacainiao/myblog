1. 优化背景与目标

1.1 业务场景分析

苍穹外卖系统面临以下高并发挑战：

  • 购物车高频操作: 用户频繁添加、删除、修改购物车商品
  • 秒杀/促销场景: 热门菜品瞬时大量下单，可能导致超卖
  • 重复提交问题: 用户快速点击下单按钮，产生重复订单
  • Token 验证压力: 每次请求都需要验证用户身份
  • 热点数据查询: 店铺状态、用户信息等频繁读取

1.2 优化目标

指标 优化前 优化后 提升幅度
购物车响应时间 50-100ms 5-10ms 10倍
下单响应时间 200-300ms 50-80ms 3-4倍
数据库 QPS 500-800 100-200 降低 75%
库存扣减并发安全 ❌ 可能超卖 ✅ 原子操作 100%安全
Token 验证耗时 20-30ms 2-3ms 10倍

1.3 技术选型

  • Redis: 高性能内存数据库，用于缓存和分布式锁
  • Redisson: Redis 客户端，提供分布式锁等高级功能
  • Lua 脚本: 保证 Redis 操作的原子性
  • StringRedisTemplate: Spring Data Redis 提供的模板类

8. 注意事项与最佳实践

8.1 库存预热

问题: Redis 重启后库存数据丢失

解决方案: 系统启动时从数据库加载库存

8.2 购物车持久化

问题: Redis 数据丢失导致购物车清空

解决方案: 定时任务同步到数据库

8.3 降级策略

问题: Redis 故障时系统不可用

解决方案: 降级到数据库操作

8.4 缓存一致性

策略: Cache Aside Pattern（旁路缓存模式）

注意:

  • ❌ 不要先删缓存再更新数据库（可能导致脏数据）
  • ✅ 删除缓存失败时，可以使用消息队列重试

8.5 大 Key 问题

问题: Hash 中 field 过多导致性能下降

解决方案:

  • 限制每个用户购物车商品数量（如最多 50 个）
  • 定期清理过期购物车

8.6 监控与告警

监控指标:

  • Redis 内存使用率
  • Key 的数量
  • 命中率
  • 响应时间
  • 连接数

告警阈值:

  • 内存使用率 > 80%
  • 命中率 < 90%
  • 响应时间 > 10ms
  • 连接数 > 40
