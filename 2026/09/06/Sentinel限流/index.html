1.3 踩坑记录

🔴 坑1：依赖选择错误

原理：spring-cloud-starter-alibaba-sentinel 包含了 sentinel-core、sentinel-transport、sentinel-annotation-aspectj 等全部组件，自动注册 SentinelResourceAspect Bean，不需要手动配置。

🔴 坑2：版本兼容性

Spring Boot 版本 Spring Cloud Alibaba 版本
3.3.x 2023.0.3.2
3.0.x 2022.0.0.0
2.6.x 2021.0.5.0

教训：Spring Cloud Alibaba 的版本号不是随意的，它对应 Spring Boot 的大版本。选错版本会启动报错。

🟡 坑3：blockHandler 方法签名必须一致

原理：Sentinel 通过反射调用 blockHandler，参数列表必须匹配，否则运行时找不到方法。

2.1 测试计划结构

2.2 关键配置

配置项 说明
Ramp-Up 所有线程在 N 秒内全部启动，模拟瞬时并发

2.3 踩坑记录

🔴 坑1：预热失败导致整个测试停止

线程组1（库存预热）设置了 on_sample_error = stoptest，预热请求失败后整个测试计划停了，后面的秒杀压测都没执行。

解决：把错误策略改为 continue，即使预热失败也继续执行后续测试。

🟡 坑2：应用没启动就跑 JMeter

Spring Boot 因为 RabbitMQ 队列 TTL 冲突没启动成功，JMeter 所有请求都连接失败。

教训：先确认应用正常启动（看到 Started MiaoShaApplication），再跑 JMeter。

三、RabbitMQ 队列 TTL 冲突

3.1 报错信息

3.2 原因分析

RabbitMQ 队列一旦创建，参数（TTL、DLX 等）就不能修改。代码尝试用不同 TTL 声明同名队列，RabbitMQ 直接拒绝。

3.3 解决方法

  1. 打开 RabbitMQ 管理面板 http://192.168.100.128:15672
  2. 找到 miaosha.delay.queue → 删除
  3. 重启应用，让代码重新创建队列

经验：修改队列参数（TTL、DLX、消息格式等）前，必须先删旧队列。生产环境要谨慎，因为删队列会丢消息。

四、项目收尾修复（4个问题）

4.1 🔴 缺少 @EnableRetry

问题：yaml 配了 retry 参数，pom 加了 spring-retry 依赖，但启动类没加 @EnableRetry，重试机制完全不生效。

原理：Spring Retry 基于 AOP 实现，@EnableRetry 会注册一个 BeanPostProcessor，扫描所有 Bean 上的 @Retryable 注解并生成代理。没有这个注解，所有重试配置都是摆设。

4.2 🔴 OrderConsumer 消息未 ack

问题：save 返回 false 时代码直接结束了，没有调用 basicAck。RabbitMQ 认为消息没被处理，会不断重发，导致消息无限堆积。

教训：手动 ack 模式下，每条消息必须被 ack 或 nack，否则 RabbitMQ 会一直等待并重投。这是一个容易被忽视但后果严重的 bug。

4.3 🟡 Redis Key 前缀不统一

为什么重要：

  1. 统一前缀方便在 Redis 中用 KEYS miaosha:* 查找所有业务 key
  2. 避免和其他业务的 key 冲突
  3. 方便设置统一的过期策略

4.4 🟡 Jackson 版本过旧

原理：Spring Boot Parent POM 里已经管理了所有 Jackson 组件的版本。手动指定旧版本会导致不同 Jackson 组件版本不一致，可能引发序列化异常。

五、关键知识点总结

5.1 Sentinel 限流核心概念

概念 说明
资源（Resource） 被保护的代码，用 @SentinelResource 标记
规则（Rule） 限流阈值（QPS、线程数等）
流控效果 快速失败 / Warm Up / 排队等待
blockHandler 被限流时的降级方法
fallback 业务异常时的降级方法

5.2 RabbitMQ 手动 ack 规范

5.3 Spring Boot 注解速查

注解 作用 不加的后果
@EnableRetry 启用 Spring Retry 重试配置全部失效
@EnableScheduling 启用定时任务 @Scheduled 不执行
@EnableAspectJAutoProxy 启用 AOP 自定义切面不生效
@EnableCaching 启用缓存 @Cacheable 不生效

六、踩坑 Checklist

  • 使用 Spring Cloud Alibaba 组件时，版本号是否和 Spring Boot 版本对应？
  • @SentinelResource 的 blockHandler 方法签名是否和原方法一致？
  • RabbitMQ 手动 ack 模式下，每条消息是否都有 ack/nack？
  • 修改 RabbitMQ 队列参数前，是否先删除了旧队列？
  • 使用 Spring Retry 时，是否加了 @EnableRetry？
  • Redis key 是否使用了统一前缀？
  • Jackson 组件版本是否由 Spring Boot 统一管理（不手动指定）？
  • 跑 JMeter 前，应用是否已正常启动？
