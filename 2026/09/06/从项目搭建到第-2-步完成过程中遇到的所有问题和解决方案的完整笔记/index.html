2. Redis 连接失败（Connection refused）

报错：

原因：本地 Redis 服务未启动。

解决：启动本地 Redis 服务，确保 127.0.0.1:6379 可访问。

知识点：Spring Boot 项目启动时会立即尝试连接 Redis（Redisson 自动配置），如果连不上会直接启动失败。开发时务必确保 Redis 已启动。

3. Redis 密码配置导致 AUTH 错误

报错：

原因：application.yaml 中 password: 后面为空值：

Redisson 检测到 password 字段存在（即使是空字符串），就会发送 AUTH 认证命令，而 Redis 没有设置密码，拒绝认证。

解决：彻底删除 password 这一行，而不是留空。

知识点：YAML 中 key: 空值 ≠ 没有这个字段。空值会被解析为 null 或空字符串，Redisson 仍会尝试认证。正确做法是整行删除。

三、架构设计类问题

14. @PostConstruct vs ApplicationRunner

问题：用 @PostConstruct 做库存预热，在 Bean 初始化阶段执行，此时 Spring 上下文可能未完全就绪，有启动失败风险。

解决：改用 ApplicationRunner，在所有 Bean 就绪、应用完全启动后执行。

对比项 @PostConstruct ApplicationRunner
执行时机 Bean 创建时 应用完全启动后
依赖状态 当前 Bean 依赖 OK 所有依赖都 OK
出错影响 项目启动失败 可捕获异常，不影响启动
适合场景 简单变量初始化 需要多组件协作的任务

五、经验总结

类别 经验
配置 YAML 空值 ≠ 没有字段，不要的配置整行删除
配置 中间件暂时不用时，用 exclude 排除自动配置
编码 金额必须用 BigDecimal，不能用 Double/Float
编码 面向接口编程，注入接口而非实现类
编码 对象存 Redis 要序列化为 JSON，不能直接 toString()
设计 Redis key 设计：业务:模块:标识，用冒号分隔
设计 ServiceImpl<Mapper, Entity> 泛型必须对应同一张表
设计 @PostConstruct 适合简单初始化，复杂任务用 ApplicationRunner
排查 查不到数据时，先检查查询条件和数据库数据是否匹配
排查 连接失败先看服务是否启动，再看配置是否正确
