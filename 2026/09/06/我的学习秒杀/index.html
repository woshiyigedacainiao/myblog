二、核心流程（全链路时序）

阶段 1：秒杀开始前 —— 库存预热

要点：

  • 库存数据提前从 MySQL 同步到 Redis
  • Redis 用 String 类型 存储剩余库存，方便 Lua 脚本原子操作
  • 同时缓存商品信息，减少 DB 查询

阶段 2：用户请求秒杀 —— 核心主流程

为什么要这个顺序？

步骤 目的
① 接口防刷 挡住恶意刷接口的请求，保护后面所有资源
② Sentinel 限流 系统级保护，控制总 QPS
③ Redisson 分布式锁 保证同一时刻只有一个线程执行库存判断+扣减
④ Redis Lua 预减库存 原子操作，高并发下不会超卖，且速度极快
⑤ 发送 MQ 消息 异步削峰，快速返回用户，后端慢慢处理

阶段 3：异步下单 —— 消费者处理

要点：

  • 幂等性：通过 uk_user_goods 唯一索引 + 业务层判断，防止重复消费
  • DB 兜底：UPDATE ... WHERE stock > 0，最后一道防线
  • 延迟消息：订单创建后立即发送一个 30 分钟的延迟消息
